@dotk/sdk-tx by example

This page walks through every operation the package builds: a registration, a records save, a subname, a transfer, a release and a sweep. Each one shows the code, the plan it answers with, and the point where the wallet asks the person to sign.

Nothing on this page runs. Every operation here spends coins and needs a signature, so a page that ran them would need your wallet and your money. Read it beside the package, and copy what you need.

The figures are real. They come from a plan this package built against mainnet's deployment, for the five-letter name alice.k, at the fee floor a node relays at. Your own numbers move with the name's length, with the node's feerate and with the coins the wallet holds. A sompi is 1e-8 KAS.

What you wire up

The package holds no key and dials nothing. You give it a node, a signer and the account that owns the names. The read client from @dotk/sdk comes with it, because a plan reads the registry before it builds.

A signer is a wallet reduced to one method. It signs the inputs this package names, by index, under SIGHASH_ALL, and it changes nothing else. KasWare's signPskt and Kastle's signTx both do this.

Without a wasm client, nodesOverWrpc(call, network) takes any transport, and WrpcJson.connect('ws://your-node:18110') is a client of this package's own. A node must run with --rpclisten-json to answer that one, and it must be new enough to report covenant ids.

Register a name

A registration is two transactions. The commit splits the gap that covers the name and writes a PENDING deed holding the bond and the deposit. The reveal spends that deed, pays the tier to the devfund and leaves the deed ACTIVE.

Both halves are built and measured before either one is signed, because the commit's change funds the reveal. A funding amount that leaves the commit relayable can put the reveal under KIP-9's storage floor, and nothing about the commit says so. Both signatures come before the commit goes out, so a refusal at the wallet costs a prompt and not a name committed to and unrevealed.

Between the two halves the name is reserved and the deposit is at risk. A PENDING deed that nobody reveals can be evicted after t_evict, 3000 DAA, which is about five minutes. The deposit goes to whoever evicts it.

Price it before you build, and make sure that the name is free, both through the read client:

totalToFund is what the wallet must hold, 40 KAS, with the network fee left out. The deposit comes back on the reveal, so what has to be on hand is the larger of the deposit and the tier, never their sum.

Finish a half-landed registration

If the commit lands and the node refuses the reveal, the name is reserved and nothing owns it yet. register says so and names the way back in. The reveal carries no signature of its own, so this account can rebuild it on a fresh coin.

The PENDING deed is found by deriving its address and reading the chain, so this works from any machine that holds the name and the owner key.

Save records

A name's records ride in a card, which is one output beside the deed. A save is therefore a transfer to the owner the deed already has. It sweeps the live card and mints the new one, so the value of a card comes back in the same transaction it goes out in.

A save merges. Every value of the live card under a key the given set does not name is carried into the new card, opaque values and sub: entries alike. Show carried and dropped before the wallet opens, because a payee list built from values this package recognizes can never name an opaque one.

Clearing is the same transfer with nothing minted:

cardRead: false means this package could not read the live card, through a missing API, a name the API does not know, a card the node refutes, or a listing it could not read. A records save throws on the last case, because a save writes the card back. A mint that follows a false here can drop what nobody can read.

Point a subname at an address

A sub: record points a label at an address. bob.alice.k is the label bob on the card of alice.k, and @dotk/sdk resolves it. The payee is the claim of the name's owner, and the chain proves none of it.

The label bob is unchanged and still there, because the save carried it. Show subnames before the wallet signs. An added, a changed and a refused entry each show in full, and the unchanged payees fold into a count. A refused entry carries address: null and a fault tag, and it never folds.

A transfer retires the card, so it ends every subname on it. Three plans do that: a transfer that mints no card, a transfer to another owner, and a sweep.

Hand a name over

A transfer moves the deed to the address you name. It sweeps this account's cards on the name by default, because moving the deed retires them.

Show recipient to the person. fromDeed and toDeed are script addresses that a reader cannot check against anything they know.

Two options change what rides along:

transfer(name, to) plans, signs and sends in one call, for a screen that shows nothing in between.

End a registration

A release kills the deed and merges the two gaps that flanked it into one. The transaction takes the predecessor gap, the deed and the successor gap, and writes a single widened gap. Only the deed's seat is signed, and the other two consent by being present.

Show returned, because it is what the balance changes by. The two flanking gaps come from the API and each one is proved against the node before the build. A gap's address hashes from its bounds, and nothing in the name yields them, so a node can confirm a pair but never find one. A client with no API passes them itself as { neighbours }.

Reclaim leftover cards

A card holds 0.5 KAS, and it is the spender's to take back. A transfer sweeps the ones it retires. Anything left from { sweep: false }, or minted by a name this account no longer holds, comes back here. The cards pay for it, so this transaction needs no coin.

A sweep takes what the API lists for the account's key and the node still holds. A client built with api: null lists nothing, so it sweeps nothing.

What the wallet is asked

Every plan carries a request you can hand a wallet as it stands. The registration carries one on each half. The indices are the ones from the transfer above.

An owner input pays to a P2SH address derived from the name, or from a card's state. A wallet that matches inputs against its own addresses finds nothing there and signs none of them, which is why the signing goes by index. Each signature is 65 bytes, 64 of signature and then 0x01 for SIGHASH_ALL. A funding input comes back as one 66-byte push. An owner input comes back as the script it was given, with its 65 zero bytes overwritten in place.

This package verifies every signature against the assembled transaction before it sends anything. A wallet that signs the wrong input, the wrong sighash type or nothing at all is caught here, and the node never sees it.

When something refuses

A plan is built and measured before a wallet opens, so a refusal costs nothing. Everything this package throws extends DotkError from @dotk/sdk, and its own classes extend TxError.

Error When
InsufficientFundingError the wallet holds too little, or holds no coin at all where one has to sign the change
FeeCeilingError the fee came out above 5 KAS, which is a rail and never a setting
MassCeilingError a node will not carry the transaction, over one of the three mass caps
SigningError the wallet's answer is not one this package can use
SubmitError the node refused the transaction, and verdict says whether a retry can help
UndecodableCardError a live card's blob is not a record set, and a save would wipe what it cannot read
NodeError the node could not be reached, or refused the call before it had an opinion

After a submission whose outcome is unknown, a dropped socket, a timeout or a cancel in flight, the coins it spent count as spent. The next plan therefore cannot offer them to a second prompt. Call registrar.resync() once the node's view has settled, such as after the transaction shows up or after a minute has passed.

@dotk/sdk-tx builds, signs and sends. @dotk/sdk reads, and its own example page runs live in a browser. dotk.name is the web app.
